# Маркетингова аналітика: опис рішення для керівництва

## Що зроблено

Система автоматичного збору статистики з рекламних платформ (Facebook/Meta, Google Ads, TikTok) через офіційні API з збереженням у локальну базу даних SQLite.

---

## Плюси обраного рішення

| Критерій | Опис |
|----------|------|
| **Простота** | Один файл бази даних — не потрібен окремий сервер, налаштування, підтримка |
| **Вартість** | Повністю безкоштовно: SQLite, Python, бібліотеки з відкритим кодом |
| **Швидкий старт** | Можна почати роботу за 1–2 години після отримання API-ключа |
| **Автономність** | Дані зберігаються локально, немає залежності від зовнішніх хмарних сервісів |
| **Гнучкість** | SQL дає повний контроль над запитами, агрегацією та звітами |
| **Масштабованість** | Підходить для обсягу до кількох мільйонів записів без втрати швидкості |
| **Переносимість** | Файл `.db` можна копіювати, бекапити, передавати між середовищами |
| **Інтеграція** | Готові колектори під 3 основні платформи, легко додати нові |

---

## Мінуси та обмеження

| Критерій | Опис |
|----------|------|
| **Один користувач** | SQLite не оптимізована для паралельного доступу десятків користувачів одночасно |
| **Локальне зберігання** | Дані на одному комп’ютері — потрібна дисципліна щодо бекапів |
| **Без веб-інтерфейсу** | Зараз тільки SQL/скрипти; для візуалізації потрібен окремий інструмент (Excel, Metabase, BI-система) |
| **API-ключі** | Потрібно отримати та підтримувати доступ до API кожної платформи |
| **Доступ до даних** | Для команди без SQL потрібні експорти в Excel або простий дашборд |

---

## Що можна робити зараз

- Автоматичний щоденний збір статистики з усіх підключених платформ
- Звіти за витратами, показниками, конверсіями по кампаніях
- Порівняння ефективності між платформами (Facebook vs Google vs TikTok)
- Розрахунок ROI, CPA, ROAS по кампаніях
- Експорт даних в CSV/Excel для презентацій
- Налаштування cron/планувальника для автоматичного збору

---

## Що можна зробити в майбутньому

### Короткостроково (1–3 місяці)

| Задача | Опис |
|--------|------|
| Додаткові платформи | LinkedIn, Twitter/X, Pinterest — по тій самій схемі |
| Простий дашборд | Веб-сторінка або Excel з графіками через Streamlit / Grafana / Metabase |
| Експорт у Excel | Автоматична генерація щотижневих/щомісячних звітів |
| Бекапи | Автоматичне резервне копіювання бази в хмару (Google Drive, Dropbox) |

### Середньостроково (3–6 місяців)

| Задача | Опис |
|--------|------|
| Міграція на PostgreSQL | Якщо з’являться кілька користувачів або потреба в веб-доступі |
| Централізований бекап | Щоденне копіювання на сервер/хмару |
| Інтеграція з CRM | Зв’язок з даними по клієнтах, лидами, продажами |

### Довгостроково (6+ місяців)

| Задача | Опис |
|--------|------|
| BigQuery / Snowflake | Якщо обсяги даних стануть великими або потрібна інтеграція з іншими джерелами |
| ML-прогнози | Прогнозування витрат, конверсій, рекомендації бюджетів |
| Real-time дашборди | Онлайн-моніторинг кампаній у реальному часі |
| Attribution-моделі | Аналіз впливу кожного каналу на конверсії |

---

## Резюме

**Поточне рішення** — недорогий і швидкий варіант для старту зі збору маркетингової статистики. Воно добре масштабується і може бути поступово розширене до повноцінної BI-системи без переписування існуючої архітектури даних.
